# Study 44: Download spikes under a publisher traffic filter

## Decision and acceptance

How often does a fixed download-spike flag change when a publisher traffic filter is applied to both current counts and their historical baseline? Compare paired factual aggregate counters, not inferred package demand. The deliverable is a bounded retrospective accounting study and local implementation exercise. The original proposal named direct BigQuery execution and version-level holdouts. This exact scope instead uses the public PSF-hosted PyPIStats overall API, with separate package and time evaluation. No direct BigQuery execution, version-specific analysis, actual bot identification, user/adoption measure or anomaly-accuracy label is claimed. Preserve the original proposal.

Pass requires pre-acquisition source/cohort rules; exact private source entities and independently reconstructed public projection; complete accounting/missingness ledger; committed development/exercise/checker dependency freeze before final scores; every threshold and both change directions; independently recomputed denominators/scores/flags; boundary fixtures; offline source-preserving replay on two Python runtimes; three source-bound inspected figures; rendered/source-bound manuscript; scoped publication audit; passing exact candidate/main Linux CI, matching tree and annotated remote tag. Per-criterion pass earns 4/5 for these finite requirements, not novelty or production reliability. At most three substantive review rounds, forty-five active review minutes and sixty review-specific calls. Acquisition/execution are separate; unknown gates prevent completion.

## Fixed comparison, no tuning or labels

For each view x, current date t: z=(log(1+x_t)-median(log(1+x on prior28 dates)))/max(MAD(log(1+x on prior28 dates)),0.1). MAD is median absolute deviation from that prior median, unscaled. Window 28 is an authored four-calendar-week context; floor 0.1 log unit is an authored numerical guard, not an estimated noise level. One-sided strict flag z>k. Primary k=6; retain k=3,6,9 sensitivity with no search, fitting, winning threshold or parameter optimization. No probability or true-anomaly label exists here.

Views: native W relative to W history; filtered U relative to U history; secondary current-only U relative to W history. Record native-cleared and filtered-appeared directions, all joint flag counts, per-package and pooled/equal-package rates, paired sample denominators, R/W accounting and extreme cases chosen deterministically by absolute native-minus-filtered score then package/date. The secondary view distinguishes changing today's counter from changing its baseline. Processing differences are deterministic accounting comparisons, not causal effects of bots, false positives, measured analyst time savings or real demand. Packages/dates are dependent, so no independent-observation confidence intervals. Raw downloads are unstandardized and shouldn't be summed into a popularity league table.

Independent checker uses separate SQLite calendar joins/integer sums and Decimal80 ln/median/MAD without importing analytical helpers. Compare finite numeric scores within absolute 1e-10 and require exact flag agreement for all thresholds; any boundary disagreement fails and is documented, not nudged. Independent exact threshold fixtures use supplied score boundaries as well as zero/constant/huge-count histories. Freeze protocol, source/assignment/projection, code, checkers, fixtures, authored exercise, development outputs and verification before any final extraction. No post-final tuning. A required later defect correction retains all prior evidence and makes reused final evaluation retrospective.

## Practical use and limits

Offline CLI accepts authored paired integer histories and returns transparent scores, both flag-change directions and UNKNOWN for insufficient/missing history. It performs no network calls or outgoing alert messages. Exercise covers a removed current spike and a newly visible spike after baseline filtering. A changed flag means inspect the traffic definition and deployment/release context before allocating attention. It cannot establish an anomaly, incident, security finding, adoption trend, saved effort or production readiness. Report zero changes or reversed direction honestly. Reproduction uses saved public aggregates; live refresh is an explicit separate acquisition, not CI.
